# 开源与商业路线图

## 发布层级

`planning`：当前文档包，未实现应用。
`prototype`：M0/M1，验证基本运行，不承诺复杂任务安全完成。
`alpha`：M2/M3，受信任项目试用，拥有并行 DAG 与共享上下文。
`beta`：M4/M5，审批、恢复、动态编辑进入完整测试。
`local-stable`：M6，满足发布门禁的开源本地版。
`extensions`：M7，逐项集成，不统一承诺全部功能同时上线。

版本号由实现仓库在发布时确定，以上不是已经存在的 release。

## 开源版始终保留

四角色与配置、完整本地 DAG、双 CLI Adapter、共享记忆、工作树、
审批、审查返工、恢复、执行日志/安全审计、配置导入导出、无限本地项目。
本地预算和资源配额不因为商业版存在而锁定。
开放 CLI/Sandbox/SCM 扩展契约；独立的本地/自托管 worker 可进入开源路线。

## 独立付费团队版

团队工作空间、多人协作、组织权限、SSO/SCIM、集中策略、
组织 Secrets Vault、集中审计和报表、托管控制平面、企业支持与计费。
可采用独立仓库或私有扩展包，依赖开源核心公开 API。
企业能力不得成为开源核心启动、测试或构建的必要依赖。

## 不属于当前承诺

用户自定义第五种角色、节点级 Profile 覆盖、自动模型 fallback、
投票/辩论/智能模型选择、订阅账号池共享，均不因为“完整目标”一词自动纳入。
这类产品行为变更需要新的明确需求和 ADR。
容器、远程 worker、企业多租户分别验收，不能把“接口预留”宣传为已完成。

## 商业发布前审查

核实模型/CLI 供应商授权、账号隔离、数据发送授权和团队使用条款。
确认 Apache-2.0 候选是否正式采用，以及第三方依赖与代码来源。
同一开源核心未来不得被宣称可以随意收回现有贡献者的授权。
涉及商标、专利、贡献权与订阅条款的结论需要发布前法律核查。
