# 产品规格

## 问题与目标

用户需要把同一开发任务分配给不同职责的 Agent，并用不同 CLI/Profile 承担决策与实现。
工具负责可观察、可恢复、可追溯的协作，不只是并排打开多个窗口。
用户可以把不同角色分配给同一模型，也可以选择不同模型；产品不内置模型品牌优劣规则。

核心体验：添加本地仓库 → 配置 CLI Profile → 绑定四个角色 → 描述需求 →
审核 DAG 与高风险操作 → 查看并行执行 → 查看候选 diff 与测试证据 → 接受结果。

## 使用场景与验收

| 场景 | 行为 | 验收条件 |
|---|---|---|
| 新建项目 | 选择本地 Git 根目录并确认信任 | 检查路径、dirty 状态、CLI execution target |
| 配置角色 | 每个内置角色选择一个 Profile | 不可选多个；节点编辑器没有覆盖字段 |
| 新建任务 | 输入目标、约束、验收条件 | Coordinator 输出经 Schema 校验的 DAG |
| 并行实现 | Developer 根据 capabilityTags 分支执行 | 并行任务使用不同 worktree，竞争资源有租约 |
| 共享上下文 | 后继读取已完成依赖的产物与记忆 | 可查每条上下文的来源、版本与 hash |
| 代码审查 | Reviewer 审查固定候选 SHA | 报告绑定 candidateSha 与测试证据 |
| 返工 | Reviewer 提出修复项 | 新增修复节点与复审节点，不产生图内回边 |
| 人工介入 | 展示具体动作、范围、风险、有效期 | 用户批准不等于全局永久放行 |
| 恢复 | daemon 中断后展示未完成执行 | 无重复写入、保留工作树和未提交修改 |
| 最终交付 | 展示 task 分支与 final diff | 不静默更改用户 main 或远程仓库 |

## 界面范围

项目页展示任务、仓库状态和 Profile 健康度。Profile 页展示 CLI 路径、配置目录、
模型请求值、观测到的模型与探测能力。角色页只有四张角色卡及其绑定/授权。
任务页包括 DAG、节点详情、实时事件、Artifacts、Memory、审批中心和最终 diff。
设置页包含资源并发、保留策略、执行信任模式和版本兼容信息。

DAG 节点可编辑标题、角色、依赖、capabilityTags、验收条件；不能编辑 model/Profile。
运行或完成节点不能原地改变定义。编辑创建新 revision，必要时让受影响后继失效并重跑。

## 成功指标（目标，不是现有测量）

基准任务至少覆盖“顺序”“并行后汇合”“返工”“等待审批”“崩溃恢复”五类。
确定性 Fake CLI 测试中重复执行造成的二次提交应为 0。
配置冲突、能力不满足、循环依赖必须在启动 CLI 之前报错。
实时事件目标：本机低负载下 p95 从持久化到 UI 可见不超过 1 秒；M0 记录硬件与负载。
多模型质量、时延和成本只能基于真实执行统计，不声称比人工或单模型更好。

## 分期边界

完整本地版包括可编辑动态 DAG、四角色、共享记忆、代码隔离、审批、
恢复、并发、受限预算、测试、日志、插件接口与后续本地 SCM 集成。
远程 worker 和可选容器执行为开源扩展方向。
组织控制平面、多人协作、SSO、集中 Secrets 与计费属于独立商业产品，
不阻断开源本地功能。

## 设计限制

Model ID 为开放字符串或 CLI 默认值。实际可运行取决于所选 CLI、网关协议、
认证、工具调用与功能兼容；UI 明确展示 verified / unverified / unsupported。
用户选择同一 Profile 给 Developer 和 Reviewer 时，系统只能保证不同 Execution/session，
不能声称实现了独立模型交叉验证。
